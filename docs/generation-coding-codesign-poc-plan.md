# POC 计划书：生成-编码协同（Generation-Coding Co-design）—— Training-Free 先验桥接

> 本文是 AIGC 生成-编码协同方向的总 POC 计划书。仓库中的
> [`semantic-roi-poc`](../semantic-roi-poc/README.md) 已实现本计划的一个子集
> （P0-B 中"语义 → QP 分配"的图像/软件编码器最小验证），本计划是覆盖它并向
> 自适应生成步数、运动场、参考帧管理等方向扩展的总纲。

## 一、背景与核心命题

**问题**：在 AIGC 实时视频场景下，视频生成（diffusion）是计算瓶颈（几十~几百
ms/帧），下游编码（尤其 HW codec，亚毫秒~几 ms）相对廉价。传统编码器需费力重新估计
运动、几何、显著性等信息，而**这些信息生成模型在推理时已"免费"产出**。

**核心命题（统一叙事）**：

> 以 **training-free / plug-and-play** 的方式，复用预训练视频生成模型推理期产出的
> 中间量（cross-attention、去噪方差、运动场、深度），桥接给下游编码器，在不改生成
> 模型权重、不损生成质量的前提下，实现**双轴收益**——省生成算力（上游）+ 省传输码率
> （下游）。

**一次内容估计，双端受益**：同源的"内容复杂度/不确定性"信号，分别映射到"生成步数"
（算力轴）和"QP/preset/参考管理"（码率轴）。

## 二、POC 目标与范围

**验证假设（POC 要回答的核心问题）**：

1. **H1**：生成端免费先验能否在**可忽略开销（目标 < 主推理 0.3%）**下提取？
2. **H2**：用这些先验驱动编码，能否在**同质量（VMAF/PSNR）下显著降码率**？
3. **H3**：内容自适应生成步数能否在**质量基本不降**下显著减少平均步数（省瓶颈算力）？
4. **H4**：生成难度与压缩难度**正交**——双信号方案在反对角线内容（象限②③）上优于
   "单一步数驱动"baseline。

**POC 范围（做什么 / 不做什么）**：

- ✅ 做：软件编码器（x265/SVT-AV1）为主战场（接口开放、可注入、可量化）；松耦合先验
  桥接；离线/近线验证。
- ⛔ 不做（留后续）：HW UMD 修改、rate-aware 重训生成模型、区域级空间非均匀去噪、
  端到端实时部署。

## 三、创新点清单（POC 覆盖优先级）

| 编号 | 创新点 | 信号来源 | 目标编码器 | 接口 | POC 优先级 |
|------|-------|---------|-----------|------|-----------|
| **P0** | **内容自适应生成步数（⑨）** | 去噪方差/Δlatent | 编码器无关 | 生成步数 | **P0 最高（攻真瓶颈）** |
| **P0** | **语义×不确定性 二维联合 QP 分配** | cross-attention + 去噪方差 | 软件 + HW | QP/emphasis map | **P0 最高（HW 也可落地）** |
| P1 | 运动场 → ME 先验 | 生成运动场/光流 | 软件 | MV predictor/搜索起点 | P1 |
| P1 | 几何/深度 → 参考帧管理 | 深度/分层 | 软件（HW 需改 UMD） | RPS/LTR/GOP | P1 |
| P2 | 预测性 IDR | 生成条件（已知） | 通用 | forceIDR | P2（生成视频利基） |
| 后续 | rate-aware 生成 | 训练目标 | 无关 | 重训 | future work |

## 四、系统架构（松耦合数据流）

1. **生成模型推理**（不改权重）→ 旁路抽取中间量。
2. **GPU 端聚合**（关键，避免大张量 D2H）：attention 跨 head/token reduce、去噪方差
   统计、运动/深度提取 → 全在显存内 reduce + 下采样到编码块网格 → int8 量化。
3. **极小 metadata 下传**（D2H）：KB 级 QP map / MV hint / 参考策略，异步 + pinned
   memory，隐藏延迟。
4. **信号分流**：
   - 复杂度/方差 → 生成步数控制器（反馈回上游）。
   - 复杂度/不确定性/语义 → QP map 生成器 → 编码器。
   - 运动场 → ME 先验；深度 → 参考管理。
5. **编码器**（x265/SVT-AV1）消费 metadata 完成编码。

**开销预算约束**：聚合 + 通信合计 < 主推理 0.3%（理想千分之一）；手段 = 层/step 子集、
kernel 融合、复用现成 softmax、异步重叠。

## 五、分阶段实施计划

### 阶段 0：基线与基础设施（搭台）

- 选定生成模型（建议：开源视频 diffusion，如 SVD / AnimateDiff 类）与编码器
  （x265 + SVT-AV1）。
- 建立测试视频集，**特别构造覆盖四象限的序列**：①纯色静态、②静态高频纹理、
  ③平滑渐变、④剧烈运动+细节。
- 固定 baseline：固定步数生成 + 默认 preset + 默认 scenecut；记录
  VMAF/PSNR/SSIM、码率、生成耗时、编码耗时。
- 打通中间量抽取钩子（attention、latent/方差、运动、深度）。

### 阶段 1：P0-A 内容自适应生成步数（攻瓶颈）

- 实现帧级自适应步数：去噪方差/Δlatent 早停准则 + 帧间暖启动。
- 度量：平均步数下降%、生成耗时下降%、质量变化（VMAF）。
- 与现有 adaptive-step 文献划界：强调"与编码协同/视频时序暖启动"的差异。

### 阶段 2：P0-B 二维联合 QP 分配（省码率，软+硬通用接口）

- GPU 端聚合 cross-attention（语义重要性）+ 去噪方差（不确定性）。
- 融合策略：实现**乘积/门控式**（重要性×不确定性），输出 per-CTU QP delta map。
- 喂入 x265（`--qpfile`/ROI 接口）/ SVT-AV1。
- 度量：同 VMAF 下码率下降%（BD-Rate）；对比单信号（仅 ROI / 仅不确定性）证明
  1+1>2。

### 阶段 3：四象限正交性验证（验 H4，最具说服力）

- 在专门构造的②③反对角线序列上，对比"单一步数驱动 preset/QP" vs "双信号分别映射"。
- 证明：②（少步难压）双信号避免细节糊；③（多步易压）双信号避免码率浪费。

四象限映射规则（横轴=生成难度→步数；纵轴=压缩难度→preset/QP）：

| | 易压（低频/平滑/静态） | 难压（高频/纹理/剧烈运动） |
|---|---|---|
| **生成简单（少步）** | ① 纯色背景：少步 / fast、升 QP（双省） | ② 静态高频纹理：少步 / slow、降 QP |
| **生成复杂（多步）** | ③ 平滑渐变：多步 / fast、升 QP | ④ 剧烈运动+细节：多步 / slow、降 QP |

主对角线（①④）= 朴素"步数≈preset"类比成立区；反对角线（②③）= 必须靠双信号才能
正确处理的区域。

### 阶段 4：P1 软件编码器深度协同（可选/视资源）

- 运动场 → x265 ME predictor 注入：测 ME 耗时下降% + 码率下降%；含置信度门控
  （坏先验退回全搜索）。
- 深度 → 参考帧管理：静态背景 LTR 保留、遮挡感知参考列表；测码率下降%。

### 阶段 5：开销审计与整合

- 全链路 profile：聚合 FLOPs/访存、D2H 次数与延迟、kernel 融合效果。
- 验证总开销 < 主推理 0.3% 目标。
- 整合双轴收益，出端到端对比报告。

## 六、评估指标与成功标准

**码率轴**：

- BD-Rate（同质量码率节省），目标二维 QP 相对 baseline **≥ 5–10%**，且**优于单信号**。
- 关键对照：省下的算力"还给编码器提 preset"能否换来同等收益（回应最初的权衡命题）。

**算力轴**：

- 平均生成步数下降 **≥ 30–50%**，VMAF 下降 **< 0.5–1**。

**开销轴**：

- 先验提取+通信总开销 **< 主推理 0.3%**（异步后接近 0）。

**正交性（H4）**：

- 在②③象限序列上，双信号相对单一步数驱动 baseline 有**统计显著**的质量/码率优势。

## 七、风险与缓解

| 风险 | 缓解 |
|------|------|
| 坏先验（运动/QP）反伤质量 | 置信度门控，不可靠区退回编码器默认 RDO |
| 与现有 adaptive-step 工作撞车 | 差异化锚定"生成-编码协同 + 视频暖启动" |
| HW 接口受限 | POC 锁定软件编码器；HW 部分（QP map 可行 / 参考管理需 UMD）列为后续 |
| 开销吃掉收益 | 严格层/step 子集 + kernel 融合 + 异步；持续 profile |
| 真实拍摄转码无免费先验 | 战场锁定 AIGC 生成内容（先验天然免费） |

## 八、交付物

1. POC 原型代码（中间量抽取 + GPU 聚合 + 编码器对接）。
2. 四象限测试序列与评测脚本（BD-Rate、VMAF、步数、开销）。
3. 双轴收益对比报告 + 正交性验证结果。
4. HW（含 UMD 路径）与 rate-aware 生成的后续路线建议。

## 九、后续（POC 之外）

- HW 编码器：QP map 直通 + 参考管理经 UMD 修改（厂商级护城河）。
- 紧耦合：rate-aware 生成（在生成 loss 加可压缩性正则）。
- 区域级空间非均匀去噪；端到端实时流水部署。
